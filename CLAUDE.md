# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

A WordPress plugin (`[adaptive_level_test]` shortcode) that administers an adaptive ESL placement test. It uses Item Response Theory (IRT) with Bayesian EAP estimation to converge on a student's CEFR level (A2–C2). There is no build step — all PHP, JS, and CSS are loaded directly.

## Development

No build tools, no composer, no npm. Install by placing the plugin directory inside `wp-content/plugins/` on a WordPress site and activating it. The activation hook creates three custom DB tables and seeds sample questions.

To test AJAX handlers manually, use a tool like Postman or browser DevTools. Send POST requests to `wp-admin/admin-ajax.php` with `action=adaptive_test_start_test` or `action=adaptive_test_submit_answers`, including a valid `nonce` (generated by `wp_create_nonce('adaptive_level_test_nonce')`).

## Architecture

### PHP layer

| File | Responsibility |
|---|---|
| `index.php` | Plugin bootstrap: registers all hooks, the shortcode, asset enqueue, and scheduled cleanup |
| `includes/db.php` | DB schema (`dbDelta`), question fetching (`adaptive_test_get_questions`), result logging |
| `includes/ajax.php` | IRT estimator, AJAX handlers for `start_test` and `submit_answers` |
| `includes/admin-settings.php` | Admin UI: Settings API registration, question/bank CRUD, CSV import/export, log management |
| `includes/cefr-colors.php` | CEFR level → hex colour constants (Cambridge English brand colours) |
| `templates/quiz-container.php` | HTML shell rendered by the shortcode; injects PHP options into `data-*` attributes |

### JavaScript layer

`assets/js/adaptive-script.js` is a single vanilla JS object (`AdaptiveLevelQuiz`) with no framework or build system. It holds all quiz state in-memory (`state.*`) and communicates with WordPress via `fetch` + `FormData` to `admin-ajax.php`. The global `adaptive_test_ajax` object (injected by `wp_localize_script`) carries all config, i18n strings, and the nonce.

### Database tables

All three tables use `$wpdb->prefix`:
- `adaptive_questions` — question text, options (JSON), answer, CEFR level, optional per-question IRT difficulty
- `adaptive_question_banks` — named banks; one is flagged `is_default`
- `adaptive_attempt_logs` — completed test results: email, level, theta, SE, sub_level, duration

Direct `$wpdb` queries are used throughout (no WP_Query); phpcs suppression comments at the top of each file explain why.

### Adaptive algorithm

1. Test starts at B1 (5 questions/batch).
2. After each batch: ≥4 correct → advance a level; ≤2 → drop a level; 3 → stay.
3. `adaptive_test_irt_estimate()` in `ajax.php` implements a Rasch model with a Normal(0, 1.5) prior on an 81-point logit grid (−4 to +4, step 0.1). Returns θ (ability estimate) and SE.
4. Test stops when: SE falls below the configurable target, the algorithm wants to go above C2, or `max_batches` is reached.
5. `adaptive_test_sub_level()` classifies θ as `borderline` / `mid` / `strong` within the final level's segment.

The JS accumulates every answer across all batches in `state.answerLog` and sends the full history with each submission, so the server always has the complete item response vector for IRT.

### Free vs Pro extensibility

The free plugin exposes three filter hooks for a companion pro plugin to override:
- `adaptive_test_bank_limit` — return `false` to remove the 3-bank cap
- `adaptive_test_question_limit` — return `false` to remove the 150-question cap
- `adaptive_test_script_data` — add pro-only JS config (styling, share buttons, encouragement overlay)

Features gated in free: encouragement overlay (`encouragement: false`), share buttons (`share_enabled: false`), and per-question difficulty calibration (column exists but not populated by free UI).

### Security patterns

- All form submissions verified with `check_admin_referer()` or `check_ajax_referer()`.
- User input sanitised with `absint()`, `sanitize_text_field()`, `sanitize_email()`, `wp_kses_post()` as appropriate.
- Rate limiting via transients (`esl_rate_start_*` / `esl_rate_submit_*` keyed by hashed IP).
- Honeypot field (`esl_hp`) on the start form; bots that fill it get a silent success response.
- CSV import validates CEFR level against an allowlist (`['A2','B1','B2','C1','C2']`) before inserting — invalid levels break the IRT estimator.
